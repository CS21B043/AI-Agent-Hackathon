API Design:
Text Generation (Simple):

Path: /generate/text
Method: POST
Input: JSON { "prompt": "..." } (application/json)
Output: JSON { "response": "..." } (application/json)
Java Method Signature: public Response generateText(TextInput input) (where TextInput is a POJO with a prompt field).
Text Generation (Config):

Path: /generate/text/configured
Method: POST
Input: JSON { "prompt": "...", "config": { "temperature": 0.5, ... } } (application/json)
Output: JSON { "response": "..." } (application/json)
Java Method Signature: public Response generateTextConfigured(ConfiguredTextInput input) (where ConfiguredTextInput has prompt and config map/object).
Image Generation:

Path: /generate/image
Method: POST
Input: JSON { "prompt": "..." } (application/json)
Output: Image bytes (image/png or appropriate type)
Java Method Signature: public Response generateImage(ImageInput input)
Return: Response.ok(imageBytes, "image/png").build();
Image Understanding:

Path: /understand/image
Method: POST
Input: multipart/form-data with a prompt field and an image file part.
Output: JSON { "description": "..." } (application/json)
Java Method Signature: public Response understandImage(@FormDataParam("prompt") String prompt, @FormDataParam("image") InputStream imageStream, @FormDataParam("image") FormDataContentDisposition fileDetail) (Need to read bytes from imageStream and get MIME type, potentially from fileDetail or assume one).
Document Understanding:

Path: /understand/document
Method: POST
Input: multipart/form-data with a prompt field and a document file part (PDF).
Output: JSON { "summary": "..." } (application/json)
Java Method Signature: Similar to image understanding, taking prompt, InputStream, FormDataContentDisposition. Need to handle potential IOException when reading/processing the document stream. Correction: The original example uses Path, but for an API, receiving bytes (InputStream) is better. Need to temporarily save the stream to a file if the GeminiClient requires a Path.
Function Calling:

Path: /execute/function-call
Method: POST
Input: JSON { "prompt": "...", "toolsJson": "[...]" } (application/json)
Output: Raw JSON response from Gemini (application/json)
Java Method Signature: public Response executeFunctionCall(FunctionCallInput input)
Code Execution:

Path: /execute/code
Method: POST
Input: JSON { "prompt": "..." } (application/json)
Output: Raw JSON response from Gemini (application/json)
Java Method Signature: public Response executeCode(CodeInput input)


Simplest Web Server: What's the easiest way to get a web server running within a Maven project without requiring a full application server installation (like Tomcat)?

Embedded Servers: Frameworks like Spark Java, Javalin, or Spring Boot are designed for this. They bundle a lightweight server (like Jetty or Undertow) within the application JAR.
JAX-RS with Embedded Server: We can use a JAX-RS implementation (like Jersey) combined with an embedded HTTP server it supports (like Grizzly or the JDK's built-in HTTP server). This aligns more directly with the previous JAX-RS example. Jersey's integration with Grizzly is a common choice for simple setups.
Choose Jersey + Grizzly: This seems like a good balance. It uses the standard JAX-RS annotations from the previous answer but embeds the server, making it runnable directly from a main method, which feels closer to the user's current mvn exec:java workflow (though the execution purpose changes from "run once" to "start server").
